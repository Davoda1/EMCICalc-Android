# Graph and table workbench — 1.0.0

The native workbench accepts up to 20 stored/enabled series. A fresh graph is empty. Select **Series → Add series**, choose a type, enter its expression, and press **Plot**. `x`, `y`, `t`, and `theta` are local graph variables; they must not be replaced by stored variables.

Supported types are explicit `y=f(x)`, polar `r=f(theta)`, parametric `x(t),y(t)`, implicit `F(x,y)=0`, regions `F(x,y)<=0` and `F(x,y)>=0`, and three-dimensional `z=f(x,y)` surfaces. For implicit equations enter the expression whose zero is sought (for a unit circle, `x^2+y^2-1`). The surface view is a real sampled triangle mesh with depth ordering and interactive yaw/pitch/zoom; it is not a flat image or remote plot. All painting is local Qt painting. No QSvg, external plotting program or network dependency is used.

Each series records a name, visibility, color, solid/dash/dot style, angle convention, parameter interval and optional explicit-curve integral interval. RAD is the default. DEG and GRAD affect both scalar trig evaluation and polar coordinate conversion and remain attached to the series/table export. The parameter interval uses those units; selecting DEG does not silently replace an existing interval with 0–360.

A graph opened from calculation Details keeps that calculation's saved context, including the value of Ans and stored definitions. The Series page identifies saved versus current context; **Current context** explicitly switches a saved series to the current calculation environment. Sampling temporarily restores the selected context on the existing worker and restores the original context afterwards. The snapshot is preserved when saving and restoring graph configuration.

Drag 2D graphs to pan. Pinch or use +/− to zoom. **Equal axes** preserves equal physical scales, and **Grid** toggles the grid. Mouse/keyboard users can move the pointer to trace, use arrows to pan and +/− to zoom; T traces the center. Trace reports nearest returned samples, and annotation hover/tap reports a numerical bracket width. **View → Fit** fits the sampled y extent, **View → Reset** restores view bounds/3D orientation while retaining series, and **View → Clear** removes series. In 3D, dragging/arrows rotate; the explicit rotate button changes yaw and +/− zoom. The renderer normalizes x, y and z extents separately; it is a height visualization, not a metrically equal-axis 3D CAD view.

The Range page holds x/y bounds, resolution and numerical annotation visibility. Quick/Normal/Fine select total evaluation budgets of 8,000/24,000/60,000 and total wall-clock budgets of 2.5/6/12 seconds. A single in-flight engine sample may finish just after the deadline; cancellation never starts another sample. This is one global budget shared fairly across enabled series, not twenty separate unbounded jobs. When a table is requested, sampling reserves up to 2,000 evaluations and one quarter of the same time budget for its rows so slow geometry does not consume the whole job. Sampling is executed serially on the application's existing sole engine worker. Each scalar call checks cancellation; the widget accepts only the current generation. The core's scalar inspection cache avoids repeated parsing. Geometry painting, hit tests, rotation, and exports never call libqalculate.

Explicit/parametric/polar curves use bounded adaptive midpoint subdivision. Undefined values, unresolved high curvature, and discontinuities become gaps. Implicit contours use a bounded grid and triangle interpolation; each contour edge must achieve a smaller scalar residual than both initial endpoint magnitudes. A sign change alone is insufficient, avoiding false zero contours at a reciprocal pole. Numerical fixtures check `1/x`, `tan(x)`, implicit circle residuals and a reciprocal implicit pole. No finite sampler can prove a global absence of poles, isolate every root, or recover features narrower than its sampling resolution. No completeness claim is made.

Roots, curve intersections, extrema and inflection annotations are estimates from returned explicit-curve segments. Their displayed bracket widths describe sampled localization, not a rigorous residual/error bound. Integral shading is supported on explicit curves; a trapezoidal area is reported only when returned paths cover the entire selected interval without gaps. It is marked approximate and does not claim a certified quadrature tolerance. Indefinite/symbolic calculus remains in the mathematical workbench.

**Table → Generate table** samples the selected series with finite From/To/Step inputs (positive step, From <= To). At most 10,000 rows are accepted, also subject to the shared evaluation budget. Editing the input column resubmits precisely those abscissae. Explicit tables contain x/y, parametric and polar tables contain parameter and Cartesian x/y. Implicit/region/surface tables use the explicitly documented **y=0 slice**, with F or z in the z column. Invalid/undefined/budget-limited rows remain visible with status. CSV contains every returned row, the series kind and RAD/DEG/GRAD, uses 17 significant digits for finite samples, and quotes text fields. It is a numerical sample export, not an exact CAS-value export.

PNG exports the current 2D or 3D view. SVG exports 2D curve/region geometry and grid using original XML, with a clipping rectangle and escaped XML attributes. CSV exports the table. Android uses the existing Storage Access Framework export helper and treats content URIs as provider destinations. Choosing no destination cancels without error. Export controls are disabled while a new generation is pending or the result is invalid.

Configuration JSON is versioned, bounded, validated transactionally and loaded without evaluating expressions. Duplicate series IDs, >20 series, invalid colors/kinds/angles/ranges and oversized expressions are rejected. Expressions have a 4,096-character cap. Restoring configuration never plots automatically.

## Verification scope

`graphmodel_contract_tests.cpp` tests mathematical geometry, pole gaps, contour residuals, inequality area, paraboloid mesh, polar and parametric conventions, all twenty curves, global budget, cancellation, integral coverage, table/CSV round trip, edited abscissae and transactional configuration. `graphworkbench_interaction_tests.cpp` exercises native worker dispatch, stale-generation rejection, empty startup, parse-only restore, phone/landscape/tablet/small viewports, actual 3D rotation rendering, all nine locales at 100/150/200% font sizes, and all eight Calculator skins. `graphengine_contract_tests.cpp` exercises real libqalculate sampling on one worker, scoped graph variables, saved/current Ans contexts, and session restoration. These host Qt fixtures do not establish Android device or emulator behavior. See [CI](CI.md) for configured checks.

Remaining qualification requirements are Android device touch/performance, TalkBack focus and native provider failure/process-death testing. The host UI has accessible graph help plus explicit non-gesture controls, but that is not a claim that TalkBack was run. Shader hardware is unnecessary because the fallback is the actual Qt software painter.
